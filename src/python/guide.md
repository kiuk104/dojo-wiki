## 프로그램 두 개가 같은 파일을 고칠 때 — 파일 잠금 {#cross-process-file-lock}

> 🏷️ `python` `잠금` `lock` `동시 작업` · 📅 2026-11-14

**한 줄 요약:** 같은 프로그램 안의 일꾼끼리는 `threading.Lock` 으로 줄을 세우지만, **서로 다른 프로그램**끼리는 그 잠금이 안 보여요. 그때는 **파일 하나를 '열쇠'로** 써서 운영체제에게 잠가 달라고 해요.

### 문제 / 상황
Fokus Podcast 앱(서버)은 피드 목록 파일(`external.json`)을 고칠 때 `threading.RLock()` 으로 "한 번에 하나씩" 을 지켜 왔어요.
그런데 옛 에피소드에 핵심어를 채우는 **스크립트**(`scripts/backfill_keywords.py`)를 따로 돌리게 됐어요. 스크립트도 같은 파일을 고쳐요.
- 앱의 잠금은 **앱 프로그램 안에만** 있어요. 스크립트는 다른 프로그램이라 그 잠금을 몰라요.
- 둘이 동시에 "읽고 → 고치고 → 저장" 하면, 늦게 저장한 쪽이 먼저 저장한 쪽의 내용을 **덮어써서 지워요.**

### 해결
파일 하나(`outputs/_feed.lock`)를 열쇠로 정하고, 고치기 전에 운영체제에게 "이 파일 잠가 줘" 라고 해요. 이미 누가 잠갔으면 기다리거나 포기해요.
```python
import msvcrt                      # 윈도우 (맥·리눅스는 fcntl.flock)

f = open(LOCK_PATH, "a+b")
try:
    msvcrt.locking(f.fileno(), msvcrt.LK_NBLCK, 1)   # NB = 기다리지 말고 바로 결과
    잡음 = True
except OSError:
    잡음 = False                    # 다른 프로그램이 잡고 있음
```
이걸 `with` 로 쓰게 감싸 두면 앱과 스크립트가 똑같이 써요:
```python
with feed_lock.hold("핵심어 채우기 스크립트"):   # 못 잡으면 "…가 피드를 고치는 중이에요"
    피드_고치기()
```
- 앱 쪽: 게시·내리기·피드 반영·📖 읽어주기가 모두 이 잠금을 잡아요. 스크립트가 도는 중이면 안내를 띄우고 멈춰요.
- 스크립트 쪽: 시작 전에 앱에 "지금 도는 작업 있어?" 를 물어보고(`/api/publish/status`), 끝날 때까지 잠금을 쥐고 있어요.
- 누가 잡았는지는 옆 파일(`_feed.lock.json`)에 이름을 적어 두어 안내 문구에 써요.

### 왜 그런가
- 3D 비유: 팀 작업에서 같은 `.blend` 파일을 두 사람이 동시에 열고 저장하면, 나중에 저장한 사람 것만 남죠. 그래서 **체크아웃(잠금)** 하는 에셋 관리 툴(Perforce 등)을 써요. 파일 잠금이 바로 그 체크아웃이에요.
- `threading.Lock` 은 **한 프로그램 안의 메모리**에 있는 깃발이라, 다른 프로그램은 볼 수 없어요. 파일 잠금은 **운영체제**가 관리해서 모든 프로그램이 같이 봐요.
- '파일이 있으면 잠긴 것' 처럼 파일을 만들고 지우는 방식도 있지만, 프로그램이 도중에 죽으면 파일이 남아 **영원히 잠긴** 상태가 돼요. 운영체제 잠금은 프로그램이 죽으면 **저절로 풀려요.**
- 같은 프로그램 안에서 겹쳐 잡는 경우(게시 안에서 또 게시를 부르는 등)는 몇 겹인지 세어서, 맨 바깥이 끝날 때만 풀어요.

> ⚠️ 주의 잠금을 **새로 만든 코드**만 잠금을 지켜요. 이미 켜져 있던 앱은 옛 코드라 모르니까, 스크립트를 돌리기 전에 앱을 **다시 시작**해야 해요. 그래서 스크립트가 "잠금을 아는 버전인지" 먼저 확인하고, 아니면 멈춰요.
